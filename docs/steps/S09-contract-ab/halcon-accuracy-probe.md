# HALCON 準確度（ADR-004 §5 的 B1–B3）與 OpenCV 的 O1：根因探測紀錄

| 日期 | 修改者 | 說明 |
|---|---|---|
| 2026-10-13 | Claude Code (Claude Fable 5.1) | 建立：分支 `fix/halcon-accuracy` 的探測結果（修正之前）。探測程式 `tests/backend/probe_halcon_accuracy.cpp`、`probe_opencv_angle.cpp`（不列進 `tests.pro`，單獨 qmake 建置；`AOI_PROBE_SET`、`AOI_PROBE_BOARDS`、`AOI_PROBE_VARIANTS` 選板子與變體），log 在 `build/qmake-release/test-logs/probe_*.txt` |

本檔只記**事實與量測**（engineering-workflow 第 4 節的 Observed Fact），修正的決定記在 ADR-004。每個數字都是本機 Release 建置、HALCON 24.11.2（授權可用，`tst_halcon_backend` 17 passed、0 skipped）實際跑出來的；同一塊板子、同一組參數跑幾次結果相同（合成板子是確定的）。

## 0. 方法

- 板子：`tst_contract_end_to_end` 的 B1（低對比 5 MP：底 60、主體 72、電極 84，雜訊 4、模糊 1）、B2（5 MP，模糊 4）、B3（1280×960，雜訊 12、模糊 2），加上變因拆開的 B1nn（B1 不加雜訊、不模糊）、B1nb（B1 不模糊）、`perf_ab` 的 noise4／noise25／glare40，和契約測試原本的 6 種 1280×960 板子（clean、10% missing、noise 12 blur 1、10% glare、tilt 3、jitter 2）。
- 每組參數量三件事：（1）`determine_shape_model_params` 在樣本上 'auto' 選到的值；（2）模型第 1 層的點數，依位置分成主體上下邊、電極上下邊、電極外側、電極內側、其他（離設計的邊 > 1.5 px）；（3）整張影像 `find_shape_model`（MinScore 0.30）的原始匹配，分成「真」（離元件 ≤ 3 px）、「半格距」（橫向離元件 ≈ 42 px）、「其他」，各自的分數與位置、角度誤差；再接 use case（`GenerateObjectsFromSample`，門檻 0.70）看找到／誤判／重複／位置／角度（和契約測試同一個 `evaluate`）。

## 1. B1：低對比時一個都找不到

| 事實 | 數字 |
|---|---|
| 'auto' 選到的對比 | B1：contrast 5／5、min_contrast 5（雜訊 ±4、模糊 1 之後邊緣的梯度峰值只有 4–6，和雜訊同一個量級）；B1nn：13／22；B1nb：16／19 |
| 模型（B1，預設） | 419 點：主體上下邊 106、電極上下 66、電極外側 65、電極內側 62、**其他 120**（模糊帶與雜訊） |
| 原始匹配（B1，MinScore 0.30） | 841 個元件全部有匹配，分數 **中位數 0.591、最高 0.712（樣本自己）**；半格距 812 個，分數 0.38 |
| 原始匹配（B1，MinScore 0.70） | 只有樣本自己（0.712） |
| 換參數 | contrast 4–8、minContrast 1–5、greediness 0／0.5、optimization none、least_squares_high、numLevels 1–3：真匹配的分數中位數都在 0.45–0.71；contrast 12 → 模型只剩 66 點（電極為主）、分數 0.92 全部找到，但位置最大 0.95 px、角度 2.1°，半格距 0.59–0.71 |
| **預先平滑**（整張影像 3 次方框模糊、半徑 1 ≈ σ 1.4，再建模型與搜尋） | 'auto' 變成 contrast 3、min_contrast 3，模型 219 點（其他只有 5）；真匹配分數 **0.977**、半格距 0.66；use case：**841 全部找到、0 誤判、0 重複、位置 p95 0.265、最大 0.355 px**，角度最大 **0.967°**（上限 0.6°） |

結論（Conclusion）：B1 的根因是 **HALCON 'auto' 的對比門檻在「對比 12、雜訊 ±4、模糊 1」的樣本上落在雜訊的量級**：模型三成的點不在邊上，而且其他元件的弱邊緣在搜尋影像裡的梯度方向被雜訊打亂，所以每個元件的分數都在 0.6 左右、過不了 0.70。不是 greediness、不是金字塔層數。把雜訊先平滑掉，模型就乾淨、分數回到 0.98。ADR-004 §5 的兩個推測（門檻偏高、greediness 太早放棄）都不對。

## 2. B2：重模糊時的半格距誤判與重複偵測

| 事實 | 數字 |
|---|---|
| 'auto' | contrast 16／20、min_contrast 7 |
| 模型（預設） | 349 點：主體上下邊 **59**、電極上下 72、電極外側 75、電極內側 25、其他 118（模糊的邊變成鋸齒狀的多條點鏈，ASCII 圖在 `probe_halcon_map.txt`） |
| 原始匹配（MinScore 0.70） | 真 841（0.987）、**半格距 812 個，分數 0.81–0.84** |
| 半格距分數的來源 | 半格距的位置上，相鄰兩個元件的電極和模型的電極重合（極性也相同），只有主體上下邊沒有東西：分數 ≈ 1 − 主體上下邊的點數比例 ＝ 1 − 59／349 ＝ 0.83，和量到的 0.825 一致 |
| 重複偵測（570 個）的來源 | **全部來自 use case 的驗證階段**（`dup by verified=570`）：半格距的種子讓晶格預測出半格距的缺格，驗證視窗（1.5 倍範本）蓋到旁邊真的元件，找到的就是那個已經有候選的元件，被當成 Verified 加進去。把半格距的種子拿掉，重複就沒有了（下面的 ov0.2）。沒有半格距種子時 use case 沒有這個問題；但視窗驗證「找到的匹配比較靠近別的已知候選」這個漏洞仍在 use case |
| 契約測試原本的板子 | 沒有模糊時半格距的分數 0.49（電極內外側差 1.7 px 對不上）；noise4 板子也有 812 個半格距匹配在 0.726，但 MinScore 0.70 的搜尋沒有回報（金字塔高層就被淘汰） |
| **MaxOverlap 0.2** | 半格距的候選和相鄰元件的外接矩形重疊 14／56 ＝ 25%，MaxOverlap 0.5 不擋、0.3 在沒有模糊的板子不擋、**0.2 全擋**：B2、B1nn、B1nb、noise4、noise25、glare40 六塊板子半格距全部消失，真匹配的數量、分數、位置、角度完全不變；use case：B2 **0 誤判、0 重複** |
| B2 剩下的 | 位置 p95 0.536、最大 **0.754 px**，角度最大 **2.4°**（模型是鋸齒狀的點鏈，least_squares 的對準不準） |
| 預先平滑 | 半徑 1：0.553 px／1.25°；**半徑 2（≈ σ 2.6）：0.394 px／0.661°**；半徑 2 ＋ 對比 hysteresis [3, 8, min_size 6]、MinContrast 1：**0.376 px／0.581°**（過）；半徑 2 ＋ SubPixel 'interpolation'：**0.175 px／0.238°**（最好，但 'interpolation' 在反光與傾斜的板子上明顯變差，見 §5） |

結論：B2 的誤判是 **shape model 的方法本身**——重模糊之後邊緣位置的容許範圍變寬，「電極–底–電極」和「電極–主體–電極」只差主體上下邊那三成的點，分數 0.83 ≥ 0.70。'auto' 的對比在這裡不是主因（contrast 5–30 都在 0.69–0.93）。擋掉它的正確規則是 **同一個模型的兩個實例不能重疊超過兩成**（MaxOverlap 0.2）。重複偵測是 use case 對半格距種子的後果，不是獨立的問題。

## 3. B3：雜訊 12＋模糊 2 的位置

| 事實 | 數字 |
|---|---|
| 'auto' | contrast 38／38、min_contrast 20 |
| 模型（預設） | 114 點：主體上下邊 **7**、電極上下 46、電極外側 45、電極內側 2、其他 14——主體的邊（對比 90，模糊後梯度約 15 < 38）幾乎不在模型裡，模型只剩電極 |
| 原始匹配 | 168 全部找到（0.977），位置最大 0.708、角度最大 2.4° |
| 換對比 | contrast 8–30：主體邊回來了（69–72 點），但雜訊點 92–200 個，位置反而更差（最大 0.84–1.6） |
| 預先平滑 | 半徑 1：0.222 px／1.18°；**半徑 2：0.196 px／0.672°**（上限：強雜訊的角落位移 0.5 px ＝ 1.03°，過）；半徑 2 ＋ 'interpolation'：0.194／0.314 |

結論：B3 的根因是 **雜訊 12 讓 'auto' 把對比門檻拉到 38，主體的長邊掉出模型**，剩下電極的短邊，位置與角度就只靠它們；直接降門檻會把雜訊點收進來。先平滑再建模型與搜尋，主體邊回來、雜訊點不進來。

## 4. O1：OpenCV 在 B1 的角度 1.2°

| 事實 | 數字 |
|---|---|
| 角度步進變細反而更差 | 預設（第 0 層步進 1.43°）：最大 1.20°、中位數 0.23；角落 0.5 px（0.77°）：**中位數 1.28°**（840 個都在 1.2–1.4）；角落 0.25 px（0.40°）：中位數 1.19° |
| 一個典型元件的 NCC 對角度的曲線（第 0 層、每個角度的範本放在元件中心） | 步進 0.4°：−1.0:0.9253 −0.6:0.9204 **−0.2:0.9098 0.2:0.9097** 0.6:0.9199 1.0:0.9233——**在 0° 有一個凹陷**，峰在 ±1.0–1.4°。B1nb、noise12、B2 也都有同樣的凹陷（深度隨雜訊／對比的比例變化） |
| 原因 | `rotatedCrop` 用 `warpAffine` 雙線性內插：角度 0（和接近 0）的範本等於原始裁切，**帶著樣本自己的像素雜訊**；轉了角度的範本經過內插，雜訊被平掉。其他元件的雜訊和樣本的不相關，所以「去掉雜訊的範本」反而和它們更相關——分數在 0° 凹下去，拋物線內插與爬坡把角度推到 ±1° |
| 建範本前先平滑（高斯 σ 0.5／0.7／1.0，搜尋仍用原圖） | 曲線變成單峰（−0.2:0.9445 0.2:0.9445 0.6:0.9429 1.0:0.9418）；B1 角度最大 **0.75／0.65／0.66°**、中位數 0.13／0.14／0.09；noise12：0.20／0.17／0.17；B2、noise4 不變。**副作用**：平滑過的範本和「電極–底–電極」也更相關，B1 多出 118／713／795 個半格距的種子（分數 ≥ 0.70）；noise4 用方框模糊（半徑 1）也多 452 個 |
| 最近鄰內插（全部角度都不平滑） | 曲線變成階梯（±0.7° 內的範本完全相同），角度解析度沒了（全部回報 0 或 0.4°）。不可行 |

結論：O1 的機制確定（樣本雜訊只留在 0° 的範本）。能做的修正（範本先平滑）把最大值從 1.2° 降到 0.65–0.75°，仍超過 0.6°，而且會讓低對比板子出現半格距的種子（需要像 HALCON 一樣的重疊規則才能擋）。

讀法：
- **MaxOverlap 0.2 沒有副作用**，單獨就解決 B2 的誤判與重複。
- **平滑半徑 1** 在契約的 8 種板子上沒有退步（10% glare 從 0.004 變 0.057 px，仍遠在上限內），把 B1 救回來（找到、位置都過），把 B3 與 noise 12 的位置壓到上限的一半；但 B1 的角度（0.97）、B2 的位置與角度、B3 的角度（1.18 對 1.03）還過不了。
- **平滑半徑 2** 讓 B2、B3 過，但 10% glare 的角度 0.89 退步到超過上限，B1 的弱邊緣被平掉（找到但位置 1.4）。所以**沒有一個固定的半徑同時滿足三塊板子**：要依樣本的模糊程度選半徑（B1 要 1、B2／B3 要 2）。
- 'interpolation' 在模糊的板子最好、在反光與傾斜最差，不適合當預設。
- **B1 的角度**：兩個 back end 修到底都在 0.65–0.97°，都過不了 0.6°。B1 的雜訊 4 對比 12（比例 1／3）比「強雜訊」板子的雜訊 12 對比 90（1／7.5）相對更強，`ContractTolerances.h` 用絕對的雜訊振幅（≥ 12）判斷強雜訊，在這塊板子上判斷相反。

## 6. 探測時看到的其他現象（ADR-004 §5 最後一項）

- **低對比沒有雜訊時 HALCON 的半格距候選（602 個）**：'auto' 的對比在 B1nn 選 13／22，主體的邊（對比 12）掉出模型，模型只剩電極（94 點：主體上下 6、電極 88），半格距的分數 0.753 ≥ 0.70。MaxOverlap 0.2 全擋（0.3 擋不住：重疊 25%）。
- **OpenCV 在低對比沒有雜訊時的半格距候選（812 個，0.74）**：NCC 把亮度正規化之後，「電極–底–電極」（84／60／84）和「電極–主體–電極」（84／72／84）的形狀幾乎一樣。OpenCV 的 NMS 用 IoU 0.5，半格距的 IoU 只有 0.14，擋不住；要擋要用和 HALCON 同樣的「重疊面積 > 20%」規則（在 OpenCV adapter 的 `nmsMaxOverlap`，或 use case 的 `NmsOptions`，後者會動到 application）。
- noise4 板子上 HALCON 的半格距分數也有 0.726（MinScore 0.30 的搜尋），只是 MinScore 0.70 時在金字塔高層就被淘汰；這說明這類候選在真實影像上也可能出現，MaxOverlap 0.2 的規則不只為 B2。

## 7. 依樣本的模糊程度選平滑半徑（候選的自適應規則）

樣本框裡「灰階範圍（p95 − p5）／梯度的 p99（3×3 Sobel）」＝ 邊緣大約幾個像素寬：

| 板子 | 模糊半徑（產生器） | 邊寬 | 需要的平滑半徑（§5） |
|---|---|---|---|
| clean、10% glare、tilt 3、B1nn、B1nb | 0 | 1.98–2.18 | 0（現在的行為就過） |
| B1、noise4、noise 12 blur 1、noise25、glare40 | 1 | 3.87–4.25 | 1 |
| B3、B3ab | 2 | 5.26–5.65 | 2 |
| B2 | 4 | 7.86 | 2（＋'interpolation' 才過角度：LS 0.661、interp 0.238） |

候選規則「ADAPT」：邊寬 < 3 → 不平滑（零複製照舊）；3–5 → 半徑 1；≥ 5 → 半徑 2；≥ 7 → 半徑 2 ＋ SubPixel 'interpolation'（邊很寬時 least_squares 的點對準不可靠，'interpolation' 用整個分數函數）。加上 MaxOverlap 0.2。用 §5 已量到的數字推算：契約的 8 種板子與 B2、B3、noise4、noise25 全部在上限內；**只剩 B1 的角度**（LS 0.967°、least_squares_high 0.781°，上限 0.6°）。

## 8. 實作之後：濾波器的種類與次像素模式（use case 端到端，MaxOverlap 0.2）

讀法：
- **'interpolation' 不穩**：同樣 σ 的三種濾波器在 B2 給 0.24、0.60、0.91°（B3 0.31、0.39、1.28）。模糊的板子上分數對角度的曲線很平，內插對量化層級的差異就這麼敏感。least_squares 穩（0.66、0.67、0.77）。所以 adapter 不用 'interpolation'。
- **mean_image 三次（＝ 3 次方框模糊）比 gauss_filter 好**：B1 的角度 0.745 對 0.919（gauss_filter 11 的 σ 2.55 只到 ±5 個像素就截掉，方框三次的尾巴平滑）。adapter 用 mean_image。
- **B2 的角度是極限**：least_squares 在三種濾波器、三種對比設定、三種角度步進下都在 0.66–0.92°（§5 的 0.58 是方框＋hysteresis 的一次，換成 HALCON 的濾波器就 0.89），過不了 0.6°。位置（0.32–0.40 px）、召回率、誤判、重複都過。
- B1 的 0.745° 對上限 0.80° 只有 7% 的餘裕（合成板子是確定的，同一個建置每次一樣）。

- **只追蹤到金字塔第 2 層**（`find_shape_model` 的 NumLevels ＝ [層數, 2]；HALCON 的說明對失焦、雜訊的影像建議「最低層的邊緣資訊不夠，用高一層的」）：B2 0.324／0.670 → **0.215／0.575**，B3 0.158／0.670 → 0.142／0.650，noise4 0.068／0.115 → 0.053／0.095；但銳利的板子變差（tilt 3：0.020／0.115 → 0.045／0.552；10% glare 位置 0.000 → 0.074），第 3 層更差（B1、B2 出現 170 個半格距誤判、角度 5°）。所以只在邊很寬（≥ 5）時用第 2 層。

- **全部平滑的代價**：第一版（邊寬 ≥ 3 就平滑、全部 least_squares_high）讓一般板子（noise 4）的 `perf_halcon` T2b 中位數 23–38 → 52 ms、T4 p95 70 ms（預算 60）、±180° 的搜尋 96–116 → 277 ms。所以改成只有「邊很寬」或「相對雜訊高」的樣本才平滑；相對雜訊 ＝ 像素和它 3×3 平均的差的中位數 × 1.4826 ÷ 灰階範圍：B1 10.4%、B1nb 11.4%、noise25 9.3%、B3 5.7%、noise 12 blur 1 5.1%、B2 2.6%、noise4 2.2%、glare40 1.8%、乾淨 0 → 門檻 4%。

採用的設定（`HalconSearchOptions` 的預設）：MaxOverlap 0.2；邊寬 ≥ 5 → mean_image 5×5 三次、'least_squares'、只追蹤到第 2 層；否則相對雜訊 ≥ 4% → mean_image 3×3 三次、'least_squares_high'；否則不平滑、'least_squares'（和 S08 相同）。B2 的角度餘裕只有 4%（0.575 對 0.6）、B1 7%（0.745 對 0.80）。契約測試的結果在 `docs/changelog-ai.md` 2026-10-13 那一筆。
