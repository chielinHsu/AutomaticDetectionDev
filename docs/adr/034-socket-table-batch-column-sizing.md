# ADR-034 Socket 表格在批次更新後統一調整欄寬

## 修改紀錄

| 日期 | 修改者 | 說明 |
|---|---|---|
| 2026-10-29 | Codex (gpt-6.1-sol) | 依拖移逾時重現與單變因實驗，避免逐格更新時持續計算內容欄寬。 |

- 日期：2026-10-29
- 決定者：Codex (gpt-6.1-sol)
- 狀態：採用

## 背景

`SelectTool::handle` 只在放開時回報移動；拖曳中僅更新預覽。Socket 的 `SolderTeachingWindow::refresh` 在移動後逐格替換 QTableWidgetItem，搭配持續的 `QHeaderView::ResizeToContents`，造成大量內容測量與排版。1017 框選 5 框，放開後超過 10 秒仍未返回；200 框也超過 5 秒。40 框放開約 426 ms。

清除表格選取無法消除逾時。只把欄寬模式改為 Interactive，同一個 1017 框重現約 39 ms 即可返回。這支持欄寬更新是本次阻塞來源；不需要更動既有畫布或背景搜尋。

## 決定

Socket 表格使用 Interactive，資料批次更新完畢後呼叫一次 `resizeColumnsToContents()`。沿用現有儲存格，只寫入有變動的文字及 id，避免每次移動重建全部項目。保留依資料調整欄寬與手動調整功能。資料、選取、復原與拖曳交易的介面及順序維持原樣。

## 否決的替代方案

- 清除選取：實驗仍逾時。
- 將拖曳交給背景執行緒或另寫畫布：預覽本身正常，Qt Widget 也必須在 UI 執行緒更新，不能解決表格排版根因。
- 本次改成新的表格 model：超出已量測到的局部缺陷；先以最小修正恢復操作。

## 後果

每次完整更新仍會遍歷表格，容量上限仍是 5000 框；並非只更新被移動的幾列。自動 Qt 滑鼠測試覆蓋 1017 與 5000 框、框選 5 框、連續預覽、放開、Esc、Undo/Redo 與選取保留。證據與限制見 [R08 拖移診斷](../plans/active/R08-socket-teaching/tasks/drag-performance.md)。
