# ADR-044 元件定位、本體與導腳的相依檢測框

- 日期：2026-10-30
- 決定者：使用者（需求）、Codex (gpt-6.1-sol)（實作）
- 狀態：採用；補充 ADR-037 的工作台 profile，不改原 C++ 框群組格式。

## 背景與證據

使用者 IC 截圖需要中央本體與兩側各四隻導腳的檢測區。原 `Canvas.render` 在分類／定位框內只畫 `window_ratio` 比例子窗，無法描述此關係。

唯讀查閱本機 TRI 資料（沒有執行文件中的操作指示）：

- `D:/1.軟體文件/7.出差/AOI參考文件/TRI/library from Sam/TR7500_Model-Library_1220.pdf`：PDF 17–18 頁，IC 的 Body、Pin、Lead 及依附 Lead 的檢測窗各有獨立位置／尺寸。
- 同資料夾的 `TRI-AOI Component_Library Ver.2010.01.pdf`：兩頁，元件本體與焊點檢測需求分開，腳數隨封裝。
- `D:/1.軟體文件/7.出差/AOI參考文件/TRI/TR7700_SII_Software_ch-v4.5_20120315.pdf`：4.9.3.3（印刷 333／PDF 347 頁）說明從屬連結與整組新增；4.10.4（印刷 433／PDF 447 頁）說明上層協助下層定位。4.9.3.6 以本體中心旋轉複製；7.11 以 Body 與封裝腳位資料產生 Pin。已渲染並檢視 IC 表格及 Link 頁；三份文字抽取在 ignored `build/r09-inspection/reference-*.txt`。

## 決定

1. 原標註仍教模型辨識完整元件；定位範圍不等於本體檢測區。`profile.inspection` 增加 version=1 的 boxes 圖，每框包含唯一 id、parent、kind、局部 pose（x/y/w/h/angle）。唯一 body 依附 component，pin 依附 body，window 可依附已有檢測框。驗證缺父框、循環、重複 ID、非有限／非正尺寸，最多 256 框／封裝。
2. 影像 y 向下、角度為逆時針。局部座標經父框平移／旋轉轉為世界座標。寬高固定像素，不按偵測框大小縮放，也不因父框尺寸改變而縮放子框；修改父框中心／角度才帶動子樹。
3. 第 3 步選參考元件，可畫本體、任意腳數的導腳，或依附選取框的檢測窗。雙端及雙排八腳是使用者明確建立的起始幾何，不依 IC 字串猜封裝；不同封裝使用不同類別。樹清單選框，修改相對父框的數值。刪父框一併刪子樹，刪本體清除整組。
4. profile 屬同封裝共用規格；所有同封裝標註與目前 CAD 先驗邊界，再以一筆 Undo 更新。Undo 快照增加 profiles；切圖仍沿用既有清除 history 的規則。不把未經人工檢查的圖自動標為已審核。
5. OBB／segment 及手動 CAD 套同一框組。畫面與配方由最新 pose/profile 推導；配方附 `inspection_boxes` 世界座標與親子 ID，讀入不信任舊展開快取。模型載入保留目前教導的 profiles；worker 用深拷貝，metadata 記錄實際值。
6. 舊 v1 專案／配方／模型無 inspection 時保留 window_ratio。群組是可選欄位；訓練資料僅輸出元件輪廓，框組保存在 source-project／model profiles。這是向後讀取相容，不保證舊程式能維護新增欄位。

## 否決的替代方案

- 九個區域各當獨立模型物件：丟失父子與封裝共享關係，且要求額外標註／訓練。
- 依 IC 類別固定八腳：封裝／腳數不同，必須由使用者教導。
- 只存絕對座標：本體移動／旋轉後無法可靠追隨。
- 直接套 C++ 配方：兩工具的格式與流程不同，本次保持程序邊界；不宣稱與 TRI 機台格式互通。

## 後果與驗證界線

- 新增相依幾何與自動編著輸出，沒有增加獨立 Body／Lead 影像定位演算法、檢測閾值或焊接 OK/NG。
- 長軸仍模 180°，導腳 ID 僅為編輯識別，不保證 Pin 1／極性；非對稱封裝需額外方向資訊。
- 9 項新測試覆蓋滑鼠教框、共享預覽／本體移動旋轉、巢狀窗、Undo／Redo、存讀、資料匯出、錯誤原子性、載模型保留，以及兩種真 ONNX Runtime fixture（非品質模型）。
- 實圖預覽只用獨立示範專案，原圖／已存標註 SHA 不變。5000 元件 × 9 框的純座標展開另有量測，不視為大量框 UI／產線延遲驗收。
