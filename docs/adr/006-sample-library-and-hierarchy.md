# ADR-006 樣本庫與 Board › Component › Box 階層

- 日期：2026-10-05
- 決定者：使用者提出需求並選擇方向、座標單位、庫與程式的關係（S01 session，2026-10-05）；Claude Code (Claude Sonnet 5.5) 整理證據與撰寫
- 狀態：採用（核心方向、座標單位、庫與程式的關係已由使用者決定；其餘未決項目列在最後，見 `docs/ux/ux-spec.md` 第 14 節）

## 背景

S01 原型的第一版只有一個流程：框一個**樣本** → 在整張板子上找相似元件 → 推算補漏 → 產生框（流程 A）。使用者在檢視原型時指出另一種做法（他在影片中看到的）：

1. 使用者隨意框選**一塊區域**（不是樣本）。
2. 演算法把這塊區域和**樣本庫**裡所有樣本比對。
3. 找到對應的樣本，把該樣本**所有的 CAD 框**列出來（流程 B）。

使用者決定：**兩種流程並存**，並納入 S01 一起設計（2026-10-05 回答）。他還補充了資料模型的要求：

- 階層 **Board > Component > Box**。
- 畫 CAD 框要能一次建立**矩陣**（同時建立多個框）。
- 要能**同時修改相同類型的框**。
- 料件上有**相依的檢測框**：例如選到料號 8371，這個元件的檢測框是「主體 ＋ 一堆 Pin 腳」的組合。
- 樣本庫條目的建立：把流程 A 的結果存成條目，以及手動在樣本上畫 CAD 框。

使用者另外提供三份 TRI（德律科技）文件，作為「別人怎麼設計元件儲存結構、怎麼建立 CAD 檔」的參考：

- `TR7500_Model-Library_1220.pdf`（22 頁，2008-12-20）：10 種封裝（電阻、電容／電感、黃色鉭電容、二極體 SOD、電晶體 TO、MELF、SOT23、IC、排阻、排容）各一張「所需檢測框」表。
- `TRI-AOI Component_Library Ver.2010.01.pdf`（2 頁）：缺陷類型 × 封裝類型的對照表（必要／可選的檢測框，與預設的比對條件）。
- `TR7700_SII_Software_ch-v4.5_20120315.pdf`（625 頁）：軟體手冊；本 ADR 引用 §1.4、§2.2、§2.4、§2.6–2.7、§2.12、§3.4.9、§4.2、§4.9、§4.10.4、§4.11。

## 決定

### 1. 資料模型（domain）

| 層 | 名稱 | 內容 | TRI 的對應 |
|---|---|---|---|
| 1 | **Board** | 影像、名稱、元件實例清單。（多連板 Panel 不在 v0.1，見「延後」） | 程式檔 `*.pre` 的一塊板；多連板是上一層 |
| 2 | **Component**（元件實例，即一筆 CAD 記錄） | 名稱（R12、U1）、位置 x y、角度、正反面、元件類型的參照、比對狀態與分數、來源（自動／手動） | `*.aoi` CAD 檔：元件名稱、X、Y、角度、元件形式（§2.2、§4.2） |
| 3 | **Box**（檢測框） | 由元件類型與元件位姿**推導**出來的矩形；不單獨儲存 | 檢測框／window |
| — | **ComponentType**（元件類型，即樣本庫條目） | 料號（主名稱）、別名、名稱、類別（Chip／IC／Other）、參考影像、框群組清單 | Library（§4.9）；名稱索引（§4.9.7.1） |
| — | **BoxGroup**（框群組） | 三種：**Body**（主體，每個類型恰好一個）；**Pin**（矩陣：列數、欄數、水平／垂直間距、略過的格子）；**Window**（檢測窗：連結到父群組，位置與大小用**父框的比例**表示，帶演算法標籤，如 Void、Solder、Color） | Body 框、Pin 框（兩端框以內插產生，§4.9.5.2）、Window 框（Void／Solder／Color／Lead…）；Link 把子框連到父框（§4.9.3.3） |

幾何慣例：框的座標相對於**主體中心**（TRI 手冊 §4.9.8.2 也是這樣）；元件位姿＝中心座標＋角度。本版原型的角度只用 90° 的倍數。

這個模型直接表達使用者的要求：

- **矩陣**＝Pin 群組的列數／欄數／間距。改列數就一次建立（或刪除）一整排框。
- **相依的框**＝Window 群組連到父群組，父框改大小，窗跟著變（原型已驗證：Pin 寬度 9 → 12，窗寬 12.6 → 16.8）。
- **8371 ＝ 主體 ＋ Pin 矩陣 ＋ Solder 窗**（原型的預設樣本）。

### 2. 三個流程

| 流程 | 使用者做什麼 | 程式做什麼 | 結果 |
|---|---|---|---|
| A **教樣本** | 框**一個**元件 | 在整張板子找相似的，晶格推算補漏 | 一個新類型（只有主體框）加上它的所有實例；可存入樣本庫 |
| B **區域掃描** | 框**任意區域**（可含很多元件） | 把區域跟樣本庫的每個類型比對，求類型與位姿，列出每個元件的**全部框** | 每個辨識出的元件＝實例，附候選類型的分數；樣本庫沒有的元件會被計數並建議「教新樣本」 |
| C **編輯元件類型** | 雙擊元件，或在樣本庫按〔編輯〕 | 顯示該類型的參考影像與框群組；改動即時反映在所有同類型元件 | 類型更新，板上所有同類型元件一起更新 |

TRI 的 Non CAD 流程（§3.4.9）就是流程 A：在影像上框元件中心、輸入名稱與類型、用「尋找其他元件」依影像相似度自動新增，名稱用「開頭字元＋流水號」（例：R100、R101）；產出的是五個欄位的 CAD 記錄，**框是之後由元件庫依類型套上去的**（§2.7 Merge）。**TRI 沒有流程 B**：它靠 CAD 檔裡的「元件形式」欄位決定每個元件用哪個庫；流程 B 是用影像辨識代替那個欄位，是本專案相對於參考文件的新增價值。

### 3. 編輯範圍（對應 TRI 的「套用範圍」，§2.12）

TRI 的編輯對話框讓使用者選套用範圍：只這個框／依電路板／依攝影機／此類型全部元件／此類型中相同演算法的框／本顆元件上相同屬性的框／全部類型。

本版採用兩個：**這個框群組**、**此類型中所有相同種類的框**（Pin 對 Pin、Solder 窗對 Solder 窗）；因為編輯的是類型，**類型的所有元件實例一次更新**。「只改這一個元件」（實例覆寫）延後，見下。

### 4. 樣本庫的儲存與查找（給 S06）

TRI 的做法（§4.9.1、§4.9.7.1）：

- 三層：**System**（原廠、唯讀）、**Project**（和程式放在一起）、**User**（使用者自己的，可複製到別台）。查找順序 Project → User → System；存檔時，從 Project 載入的存回 Project，其他存到 User。
- **名稱索引**：主名稱＋次名稱（別名、料號）。CAD 檔裡的型號常是別稱或料號；索引把它們對到同一個庫。可由 Tab 分隔的文字檔載入。
- 載入庫時可依類別（IC／Chip／Other）、名稱、腳數、腳距、Pad 長度、本體尺寸（±200 µm）搜尋。

本專案建議：v0.1 做 **Project ＋ User 兩層**（System 層等有需要再加）、料號＋別名索引、原型已有的篩選（料號／名稱／別名／腳數）。細節 S06 定案。

### 5. 庫與板子：板子保存自己的複本（使用者決定，TRI 的 Merge 語意）

- **樣本庫**（使用者層）是類型的母版；**板子**保存自己用到的每個類型的**複本**（原型的 `p_<庫 id>`），複本記得它從哪個庫條目來（`libId`）。
- 接受一份提案時，用到的庫類型會**複製**進板子；之後改庫**不會**偷偷改到舊板子（TRI 手冊 §2.7：Merge 會把庫套用進程式，重新整合會覆蓋原資料）。
- 在板子上編輯類型（雙擊元件、按 `E`）改的是**板子的複本**，板上所有同類型元件一起更新；有兩個儲存按鈕：〔只儲存在這塊板子〕與〔儲存並存入樣本庫〕。
- 從樣本庫的〔編輯〕開啟的是**庫條目**本身，儲存後板上已有的複本**不會自動更新**。
- 兩個明確的動作：〔從樣本庫更新〕（庫 → 板子複本）與〔存入樣本庫〕（板子複本 → 庫，會覆寫同料號的條目）。選到元件時顯示「與樣本庫相同／不同／只在這塊板子上」。
- 刪除庫條目**不影響**已有的板子（它們有自己的複本）；該複本變成「只在這塊板子上」。以上每個動作都是文件堆疊上的 Command，可復原。

### 6. 座標單位（使用者決定）

樣本庫存**物理單位（µm）**，板子影像帶一個「µm／像素」的校正值，這樣庫才能跨影像、跨相機重複使用（TRI 的 §4.9.8.2 也以 µm 為單位）。S03 的座標慣例要把它寫進去，測試影像也要有校正值。原型為了簡化仍用像素，**這是原型的簡化，不是決定**。

### 7. 庫變大怎麼辦（使用者提問，2026-10-05）

問題：區域掃描要和庫裡每個樣本比對，庫很大時會很慢。原型的「比對範圍」把成本綁在**實際比對的樣本數**上，這個數字顯示在狀態列（「比對 N 個樣本」）。

1. **預設「先用板子已有的類型，找不到再擴大到整個樣本庫」**。板子本來就保存自己用到的類型複本（§5），一塊板子通常只用到庫的一小部分；第一輪只比這些，區域裡還有東西沒比到才擴大。也可以改成「只用板子已有的類型」或「整個樣本庫」。只比板子類型卻有元件可能符合其他庫樣本時，訊息會提供〔改用整個樣本庫〕。
2. **預篩選（建議，原型沒有）**：庫存 µm（§6），所以可以先偵測區域裡的零件外形（大小、長寬比），只比對本體尺寸相近的條目。TRI 載入庫的搜尋對話框就是依類別、名稱、腳數、腳距、Pad 長度、本體尺寸（±200 µm）篩（手冊 §4.9.2.2）。
3. **一次性預處理**：每個條目的比對模型（HALCON 的 shape model、OpenCV 的模板金字塔）在載入庫時建一次並快取，不要每次掃描重建。（假設）
4. **由粗到細與提早放棄**；不同條目的比對可平行。（假設）
5. **取消的粒度**是「每次比對一個條目」之間；進度可以回報「第幾個樣本」；已辨識的結果可以先顯示。（假設）

**全部沒有量測。** 每一項能省多少、成本和 N 的關係是線性還是更好，是 S07 要量的結果，不是前提：用庫大小 N ＝ 1、10、100、1 000 量 T7，並分別量有無預篩選。原型的耗時是公式模擬（基準 ×（0.6 ＋ 0.2 × 比對的樣本數）），**只有「比對了幾個樣本」是真的邏輯**。

## 證據

事實（已觀察）：

- 上述 TRI 文件內容，逐字讀過；章節號見背景。TR7500 文件的檢測框表有「Link」欄（Missing／Lead／UnLink），尺寸欄用公式（例：Void 窗＝`2/3 × Missing W` × `3/5 × Missing H`），Link 的語意在 §4.9.3.3：沒有自己定位能力的框（Void、Pin 等）靠連結到有定位能力的框（Missing、Lead、Align）來定位。
- 原型（`docs/steps/S01-ux-spec/explainer.html`）實作了本模型並用頁內腳本驗證（最終版 124 項斷言全過，另有比對範圍的專屬測試約 20 項）：三個流程、掃描辨識出 3 顆 IC（含旋轉 90° 的一顆）共 123 個框、列數改 12 得 24 支 Pin 與 24 個窗、父框改寬度子窗跟著變、同類型範圍編輯、儲存後板上 3 顆 IC 一起更新且可復原、CAD 清單 5 個欄位；**複本語意**：改庫不影響板子、〔從樣本庫更新〕與〔存入樣本庫〕、刪庫不影響板子，且每一步可復原。

假設（未驗證）：

- 區域掃描要「在區域內自己找出元件位置與角度」，需要真的比對演算法（S07／S08）。原型的比對是假的（用元件真值）。
- HALCON 端預期每個庫條目建一個 shape model 再一次找多個；OpenCV 端預期每個條目一次模板比對（成本隨庫大小 N 成長）。**這兩點都沒驗證**，S07／S08 實測；效能矩陣要加「庫大小 N」維度。
- 影片我看不到；流程 B 的理解來自使用者的文字描述。

## 否決的替代方案

- **扁平的框清單（沒有階層）**：表達不了「8371 ＝ 主體 ＋ Pin」，也沒辦法同時修改同類型的框。
- **每個元件實例各自存一份框**：38 顆電阻要改 38 次。
- **框的位置用自由文字公式（TRI 的 Model Library 用 `W = 2/3*Missing W` 這類）**：功能強，但要寫解析器、驗證與錯誤訊息。本版用數值比例（原型的表單直接輸入百分比），自由公式延後。
- **只靠影像相似度、不用料號**：CAD 檔與 BOM 用料號／型號，必須能對應；所以類型帶料號與別名。

## 後果

- **S02**：工具列 V／S／R／＋，類型編輯器的工具 V／B；dock 有樣本庫、物件樹、參數；畫布有「板子」與「類型」兩個場景；板上選取單位是元件，框的縮放只在類型編輯器（把手 24 px）。
- **S03**：新增 domain 型別 `Board`、`ComponentInstance`、`ComponentType`、`BoxGroup`（Body／Pin／Window）、`ObjectOrigin`、`NoMatchReason`；新增 port `ILibraryStore`、`ILibraryMatcher`（區域＋樣本庫 → 元件候選與位姿與分數）。
- **S04**：狀態機 8 個狀態（`docs/ux/ux-spec.md` 第 6 節）；Presenter 與介面名單（第 12 節）；復原有三個範圍（ADR-002 已更新）。
- **S05**：晶格推算改在**元件層級**（元件的陣列）；框層級的矩陣是簡單算術（`BoxGroup` 展開），不需要晶格估計。
- **S06**：樣本庫儲存（層級、名稱索引、檔案格式與版本）；**板子（元件實例＋它用到的類型複本，含 `libId`）的儲存**；座標單位 µm 與影像校正值。
- **S07／S08／S09**：`ILibraryMatcher` 的實作與契約測試（辨識正確率、排序、位姿誤差）。介面吃的是**候選清單**（範圍由呼叫端決定，見 §7），結果要附「實際比對了幾個樣本」。
- **S10**：效能矩陣加「庫大小 N」。
- **S12**：匯出 CAD 清單（5 個欄位＋正反面）與 DXF；原型有預覽。
