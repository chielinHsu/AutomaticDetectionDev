# 設計決策紀錄（ADR）

> 只新增，新紀錄放最上方。已記錄的決定，沒有新證據不推翻；要推翻就新增一筆，標明取代哪一筆。
> 專案若已用 `docs/adr/NNN-slug.md` 一檔一決策，本檔改為索引（一行一筆，連到 ADR 檔），不要兩邊各寫一份內容。

## 格式

```markdown
## D-0001 一句話標題

- 日期：YYYY-MM-DD
- 決定者：Claude Code (模型) ／ Codex (模型) ／ 使用者
- 狀態：採用 ／ 已被 D-00xx 取代
- 背景：為什麼需要做這個決定
- 決定：選了什麼
- 否決的替代方案：A 為什麼不行、B 為什麼不行
- 後果：這個決定帶來的限制，以及要注意什麼
```

## D-0001 以 AGENTS.md 與 CLAUDE.md 作為薄入口，共用規範集中在 .agents/harness 與 AI_CONTEXT.md

- 日期：{{DATE}}
- 決定者：範本
- 狀態：採用
- 背景：Codex 讀 `AGENTS.md`，Claude Code 讀 `CLAUDE.md`；兩邊各維護完整內容會漂移。
- 決定：兩個入口只放「必讀清單、不可省略的規則、平台專屬規則」；共用內容集中維護一份。
- 否決的替代方案：兩邊各寫完整規則（會漂移）；用符號連結（Windows 上不穩定，且兩個平台的專屬規則仍需要各自的檔案）。
- 後果：新增共用必讀文件時，要同步更新 `AGENTS.md` 的清單與 `CLAUDE.md` 的匯入，`check-ai-structure.ps1` 會檢查。
